# AGENTS.md

AI assistant reference for this Sanity Studio v6 project. Use this file across all AI coding assistants (Claude, Cursor, Copilot, Windsurf, Codex, Gemini, etc.).

## Commands

```bash
bun run dev          # Start Sanity Studio in development mode
bun run build        # Build Studio and extract + generate TypeScript types
bun run deploy       # Deploy Studio to Sanity hosting
bun run typegen      # Extract schema and regenerate types/sanity.types.ts (run after schema changes)
bun run typegen:watch  # Watch mode for type generation
```

## Environment Variables

Required in `.env`:
```
SANITY_STUDIO_ID="..."
SANITY_STUDIO_PREVIEW_URL="..."
SANITY_STUDIO_DATASET="production"
```

## Architecture

This is a **Sanity Studio v6** project — a headless CMS configuration only (no frontend). The output is a deployed Studio and a `types/sanity.types.ts` file consumed by separate frontend projects.

### Key config files
- `sanity.config.ts` — main config: registers plugins, schema, structure, presentation tool, singleton types
- `sanity.cli.ts` — CLI config
- `utils/env.ts` — exports `projectId` and `dataset` from env vars

### Schema (`schemaTypes/`)
- **Documents**: `home`, `page`, `header`, `footer` — `home`, `header`, `footer` are singletons (restricted to publish/discardChanges/restore actions only, no "create new" template)
- **Custom types**: locale variants (`localeString`, `localeText`, `localeBlock`, `localeSlug`), `cta`, `picture`, `video`, `media`, `seo`
- All schemas use shared field groups from `utils/groups.ts` (Page, Content, SEO tabs)

### Localization
- Languages defined in `utils/localization.ts` — currently English + Italian, English is the default (`isDefault` flag or first in array)
- Locale types wrap each field in an object keyed by language id (e.g. `{en: "...", it: "..."}`)
- The `@sanity/language-filter` plugin filters locale fields in the Studio UI; fields whose enclosing type name starts with `locale` are filtered by selected language

### Studio Structure (`structure/`)
Custom sidebar structure: **Site Navigation** (header + footer singletons), divider, **Home** singleton, **Pages** list. Defined in `structure/index.ts` and composed from individual files.

### Presentation Tool (`presentation/resolve.ts`)
Maps routes to document types for the visual editor:
- `/` → `home` document
- `/page/:slug` → `page` document matched by slug in the base language

### GROQ Queries (`queries/index.ts`)
Typed queries using `defineQuery` from `groq`. The variable name determines the generated Result type name (e.g. `HOME_QUERY` → `HOME_QUERYResult` in `types/sanity.types.ts`). After adding or modifying queries, run `bun run typegen`.

### Type Generation
`types/sanity.types.ts` is auto-generated — never edit it manually. `types/schema.json` is the extracted schema. Both are regenerated by `bun run typegen` (or automatically during `bun run build`).
